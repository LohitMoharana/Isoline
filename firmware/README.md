# Isoline firmware

`core/` is platform-independent C99, with no dynamic allocation in the streaming path. It runs unchanged on a PC (test
harnesses) and on the STM32L432 (Nucleo-L432KC carrier board, see `hardware/`).

| file | what |
|---|---|
| `core/isoline_core.[ch]` | leaky integrator, 216 integer beat features (histograms, template residual, RR, long RR, online clusters), event-based QRS detector, RR-only AF features |
| `core/isoline_stream.[ch]` | slot-by-slot streaming wrapper: push one 360 Hz slot of up/down counts, get classified-ready beats out 444 ms after the R peak; ~12 KB RAM |
| `../export/isoline_model.h` | the tree classifier + AF detector (generated by `scripts/export_c.py`, bit-exact vs scikit-learn) |

## Verification (all against the Python reference, DS1 records)

| check | result |
|---|---|
| `test/verify_core.py`, 22 DS1 records | leaky integrator identical; **50,987 / 50,987 beats** with identical 216-feature vectors; **51,772 detected beats identical**; AF features identical |
| `test/verify_stream.py`, slot-by-slot streaming | same beats and identical features/AF on 10,176 beats (records 101, 108, 203, 209) |
| `scripts/export_c.py` | tree model in C: 100.0000 % identical decisions (float leaves), 99.95 % (int8 leaves) |

Two exactness details: (1) the RR count `round(d*32/360)` is done as `(8d+45)/90` (no ties possible); (2) the AF
features reproduce numpy's `diff(r/360)` in double precision, including its ~1e-16 differences between equal-length
intervals, because the trained detector saw them.

## End to end: beats detected from events (DS2, measured once, nothing tuned)

| | beat detection | annotated beats | detected beats | end to end (missed beats = errors) |
|---|---|---|---|---|
| full + AF | **Se 99.78 %, +P 98.67 %** | 95.51 % | 94.71 % | **94.50 %** |
| tiny + AF | | 94.76 % | 93.67 % | **93.47 %** |

Using detected rather than annotated beat positions costs ≈ 0.8–1.1 points, mostly as normal beats called V (V +P 0.94 → 0.85).
The classifier was trained at annotated R positions, while the detector's fiducial is offset by a few samples.
**Next:** train on features computed at detected beat positions (decided on DS1).
